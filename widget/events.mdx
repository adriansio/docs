Listen to widget events to integrate with your application or track analytics. Add the install code from your StoreRocket dashboard to the page first; it defines the global `StoreRocket` object used below.

## Listening to Events

### Via Configuration

```js
StoreRocket.create({
  account: 'abc123',
  container: '#locator',
  on: {
    ready: (widget) => {
      console.log('Widget is ready');
    },
    locationSelect: (location, source) => {
      console.log('User selected:', location.name);
    }
  }
});
```

### After Initialization

`widget.on` uses the names in [Instance events](#instance-events) below.

```js
const widget = await StoreRocket.create({
  account: 'abc123',
  container: '#locator'
});

widget.on('select', (location) => {
  // Send to analytics
  gtag('event', 'store_select', {
    store_name: location.name,
    store_id: location.id
  });
});
```

## Configuration callbacks

Pass these inside `on:`. Only the callbacks listed here are ever called.

| Callback | Called when | Arguments |
|---|---|---|
| `ready` | The widget has finished loading | `(widget)` |
| `search` | A search has finished | `(query, results)` |
| `searchComplete` | A search has finished, with details | `(query, results, { center, radius, unit })` |
| `locationSelect` | A location is selected | `(location, source)` |
| `select` | A location is selected (older name) | `(location)` |
| `filterChange` | The active filters changed | `(activeFilters)` |
| `filtersChange` | The active filters changed (older name) | `(activeFilters)` |
| `analytics` | The widget records a tracking event | `({ event, ...data })` |
| `error` | A search or load failed | `(error)` |

```js
StoreRocket.create({
  account: 'abc123',
  container: '#locator',
  on: {
    ready: (widget) => console.log('Ready'),
    searchComplete: (query, results, meta) => {
      console.log(`Found ${results.length} results for "${query}"`, meta.radius, meta.unit);
    },
    locationSelect: (location, source) => {
      console.log('Selected:', location.name, source);
    },
    error: (error) => console.error('Widget error:', error)
  }
});
```

## Instance events

Use `widget.on(event, handler)` after the widget started. It returns a function that stops listening.

| Event | Handler receives |
|---|---|
| `ready` | the widget |
| `search` | `(query, results)` |
| `select` | the location |
| `filtersChange` | the list of active filters |
| `analytics` | `{ event, timestamp, projectId, ... }` |
| `error` | the error |

## Browser events

The widget also fires events on its container element. They bubble, so you can listen on `document`:

| Event | `event.detail` |
|---|---|
| `storerocket:ready` | `{ widget }` |
| `storerocket:search` | `{ query, results, center }` |
| `storerocket:location-view` | `{ location }` |
| `storerocket:filter-change` | `{ filters }` |
| `storerocket:radius-change` | `{ radius, unit }` |
| `storerocket:units-change` | `{ unit }` |
| `storerocket:show-all` | `{ count }` |

```js
document.addEventListener('storerocket:location-view', (e) => {
  console.log('Viewed:', e.detail.location.name);
});
```

## Google Analytics Example

```js
StoreRocket.create({
  account: 'abc123',
  container: '#locator',
  on: {
    searchComplete: (query, results) => {
      gtag('event', 'store_search', {
        search_term: query,
        results_count: results.length
      });
    },

    locationSelect: (location, source) => {
      gtag('event', 'store_select', {
        store_name: location.name,
        store_id: location.id,
        selection_source: source
      });
    }
  }
});
```
