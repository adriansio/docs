---
title: "Pick this location"
description: "A button that hands a location to your page instead of opening a link, with the event your code listens for."
---

A **Pick this location** button lets a visitor pick one of your locations without leaving your page. What your page
does with it is up to you: a checkout that asks "which store will you collect from?", a booking form, a "set my store"
header.

When a visitor presses it:

- the button reads **Selected** (the word is editable on the Languages page, in every language your locator has),
- your page receives the `storerocket-storelocator-location-pick` event with the location,
- nothing opens and the page does not navigate.

<Note>
**Pick** and **select** mean different things in this API. `selectLocation()` and `locationSelect` open a location's
details. `pickLocation()` and `locationPick` hand a location to your page.
</Note>

## Add the button

1. In the dashboard, open **Calls to Action** and press **New call to action**.
2. Type the button's words, for example `Select studio`. Visitors see your words, not the word "pick".
3. Under **When pressed**, choose **Picks the location**.
4. Leave **On every location** on, and press **Create call to action**.

The button shows on cards, map popups and the opened location on the new store locator engine, in every theme.

## Listen for the pick

```html
<script>
  document.addEventListener('storerocket-storelocator-location-pick', function (event) {
    var location = event.detail.location;
    if (!location) return; // an ID that is not on the locator (see below)
    // location.id is the location's ID, the same one the dashboard and the API use.
    document.querySelector('#pickup-store').value = location.id;
    document.querySelector('#pickup-store-name').textContent = location.name;
  });
</script>
```

The event is sent from the locator's element (`#storerocket-widget`) and bubbles, so a listener on `document` hears it.
With two locators on one page, `event.target` tells you which one.

A locator made with `StoreRocket.create()` hears the same pick as an instance event:

```js
const locator = await StoreRocket.create({
  account: 'YOUR_ACCOUNT_ID',
  container: '#locator',
  on: { locationPick: (location, detail) => console.log(location?.name, detail.source) },
});
// or later, same arguments: locator.on('locationPick', (location, detail) => { ... })
```

### `event.detail`

| Field | Type | What it is |
| --- | --- | --- |
| `location` | object \| null | The location (below), or `null` when the ID is not on the locator. |
| `location_id` | string | The location's ID. |
| `location_name` | string \| null | Its name. |
| `previous_location_id` | string \| null | The location picked before this one, if any. |
| `source` | string | `button` (a visitor pressed it), `page` (your embed's `data-storerocket-picked-location`), or `code` (`pickLocation()`). |
| `reason` | string | Only when `location` is `null`: `not_found`. |

### `event.detail.location`

| Field | Type |
| --- | --- |
| `id` | string |
| `name`, `address`, `address_line_1`, `address_line_2`, `city`, `state`, `postcode`, `country` | string \| null |
| `lat`, `lng` | number \| null |
| `phone`, `email`, `website`, `timezone` | string \| null |
| `fields` | object: your custom fields by name, for example `{"Parking": "Free"}` |
| `filters` | array of strings: the location's filter names |

A press is also counted as a normal button click: it reaches your analytics as `storerocket-storelocator-click` with
`cta_type: "pick"`, and Google Analytics as `storerocket_click`.

## Start with a location already picked

If your page already knows the visitor's location (a checkout reopened, a saved "my store"), put its ID on the embed:

```html
<div id="storerocket-widget" data-storerocket-id="YOUR_ACCOUNT_ID" data-storerocket-picked-location="LOCATION_ID"></div>
```

When the locator loads, that location's button reads Selected and your page receives
`storerocket-storelocator-location-pick` with `source: "page"`. If no visible location has that ID (a typo, a location
since deleted or hidden), the same event arrives with `location: null` and `reason: "not_found"`, so the handler that
saved the ID can forget it. To also open the map on it, add `data-storerocket-location="LOCATION_ID"`.

The Install page's builder offers this as **Already picked** once your account has a Pick this location button.

## Pick from your own code

```js
const locator = StoreRocket.get('#storerocket-widget');
locator.pickLocation('LOCATION_ID'); // the same as pressing that location's button
locator.getPickedLocation();         // the location picked last, or null
```

`pickLocation()` returns a promise with the event's `detail`, or `null` when the ID is not on the locator.

## Good to know

- The pick lasts while the page is open. Pressing another location's button moves it; pressing the picked one again
  sends the event again. There is no un-pick: a checkout always needs a location.
- The button needs the new store locator engine. On the older engine it is not shown.
- StoreRocket never runs code from your account: your page listens, the locator only tells it.
